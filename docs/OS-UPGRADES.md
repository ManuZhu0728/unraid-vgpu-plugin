# 随 Unraid 更新驱动

## 使用

保存下载地址和 Token，开启“跟随 Unraid 更新驱动”。助手会先缓存当前内核的驱动，
随后监听系统升级。升级 Unraid 后，等待 **NVIDIA vGPU Manager 的“新内核驱动已准备”通知**，
再按正常流程重启。

页面“系统升级”显示准备状态、目标内核和驱动版本。缺包或网络失败时会通知，
后台每 15 分钟重试；“检查升级准备”可立即再检查。修改地址或 Token 后也会重新检查。

默认跟随已选择的 NVIDIA 分支，不自动从 R580 跳到 R595。固定完整驱动版本时，
只下载该版本对应的新内核包。

## 首次迁移

运行管理和驱动更新是两个设置。驱动更新负责安装驱动，vGPU 开机管理负责恢复设备。
使用原插件或 User Scripts 的机器，需要先整理为一个启动入口，再安排第一次重启。
插件会识别冲突的旧驱动插件、脚本及 GPU/VFIO 占用。

开启设置时只启动下载助手；安装发生在后续开机。原缓存保留，便于随系统回退使用。

## 执行顺序

```text
开启联动 → 缓存当前内核驱动
系统更新 → 读取目标内核 → 下载并校验 → 通知准备完成
重新开机 → 安装当前内核匹配包 → 版本复核 → 恢复 vGPU → Docker/VM 启动
```

Unraid 的 `/usr` 内容在重启后重建，因此普通重启也需要从持久缓存恢复驱动。
安装器记录 Linux boot ID，区分重新开机与运行中更新插件；同一次启动失败后不重复安装。
安装或校验失败会保留缓存和历史成功记录，并停止后续 vGPU 初始化。

## 文件

| 路径 | 用途 |
| --- | --- |
| `settings.json` 的 `upgrade` | 更新开关、驱动分支和启用时的 boot ID |
| `upgrade-state.json` | 当前准备任务和目标包回执 |
| `driver-state.json` | 开机安装结果及成功回执 |
| `packages/<内核>/` | 各内核驱动缓存 |
| `/var/log/unraid-vgpu-manager-upgrade.log` | 助手运行摘要 |

前三项和缓存位于 `/boot/config/plugins/unraid-vgpu-manager/`。
助手使用独立 PHP 进程，不覆盖系统共享的 `plugin_update_helper`。

## 开发验证

运行 `bash tests/run-tests.sh`。测试使用临时文件、模拟下载源和安装命令，覆盖准备、
新内核重启、后续普通重启、重复启动、缺包、占用和安装失败。实机升级测试需在发布后
安排维护窗口；构建机不安装 NVIDIA 驱动。
