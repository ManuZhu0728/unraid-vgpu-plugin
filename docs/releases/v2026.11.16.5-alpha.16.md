# Unraid vGPU Manager 2026.11.16.5 Alpha 16

修复本地二进制分块上传的原生鉴权兼容问题，并强制要求独立 MD5 文件。

## 修复内容

- 将二进制块显式编码为 base64url，再通过普通 URL 编码表单发送；初始化、分块、完成、取消及离页取消通知均不再使用 multipart，避免原生 nginx/PHP-FPM 鉴权子请求等待请求体。
- 本地导入必须同时选择 TXZ 和对应 MD5。缺失、空白、超大、格式/包名不符或实际摘要不符均拒绝；不使用上传包自行计算的值代替来源方 MD5。旧单文件 CLI 导入入口同样强制要求 MD5。
- 保留双 CSRF、同源请求、固定 CLI、事务锁和独立会话。严格校验编码、块大小、连续偏移及总量，按 PHP POST 限制调整块大小。
- 完成回执核对包名、内核及外部 MD5，确认后仅以 GET 更新缓存。已知失败清理本会话；取消只尝试一次；鉴权失效、断网或回执未知时提示核对缓存，阻止重复最终导入，不把未知结果显示成成功或已取消。
- 补齐真实浏览器 → nginx auth_request → PHP-FPM → Application/Upload → 临时缓存的上传、取消、失败回归及旧 multipart 超时负对照。
- 完成正文、代码标识、表单、XML/日志、按钮与原生页签的字体核对，详见 [字体审计](https://github.com/ManuZhu0728/unraid-vgpu-plugin/blob/v2026.11.16.5-alpha.16/docs/UI-TYPOGRAPHY.md)。本版未修改字体 CSS。

## 7.3.4 验收

1. 将插件升级至 `2026.11.16.5`，重新打开页面，切换“驱动管理 → 本地上传”。
2. 同时选择可信来源的规范 TXZ 与对应 MD5；应显示分块上传进度及后续校验状态，成功后缓存显示正确版本、构建号和“本地导入”。
3. 缺少 MD5 不得开始上传；错误 MD5 不得替换当前缓存。上传过程中取消，应提示已取消，旧缓存仍在。
4. 若出现“结果未确认”或“清理未确认”，先使用“重新打开页面核对缓存”，不要连续点击或重复导入。离页取消是尽力通知，不保证断网时送达。

MD5 用于完整性比对，不是发布者签名，请同时从可信来源获取 TXZ 与 MD5。
此次 UI/传输修复不需要主动重启服务器；上传只写缓存，不安装驱动。后续开机安装仍受原有设置控制。

不连接、部署或操作 Unraid，不改驱动安装/启动/运行时/重新配置逻辑，不重打 NVIDIA 驱动，保留历史发布附件。
