# Alpha 18 — Unraid 原生安装与显式构建选择

插件版本：`2026.11.17.1`。修复提交：`967942a`。

## 修复

- 驱动由 Unraid 原生 `rc.modules` / pkgtools 安装；插件在既有 `.plg` 入口核验原生安装结果，
  然后初始化 vGPU，不再重复调用驱动安装器，不再只认“插件自己安装”的本次启动记录。
- 多 build 放入 `driver-cache/<内核>`；`packages/<内核>` 仅准备该内核明确选择的唯一 TXZ 与 MD5。
  下载和上传只缓存，需在已下载列表明确选择下一次启动构建。各内核选择独立，目标内核预下载不替换旧内核选择。
- 核验包名/build、原生安装来源、缓存与启动包 MD5、实际模块内容/版本/内核，以及已加载模块身份。
  核验失败不初始化，不自动换用其他缓存；核验驱动与 vGPU 初始化结果分别判断。
- 只迁移本插件的旧缓存和引用，保留所有 build 与校验文件；关闭恢复或卸载插件撤下启动副本，缓存保留。
  启动副本会额外占用一个驱动包的空间，切换时不会不断保留旧启动副本。
- 不改 Unraid 的 `rc.modules`、`rc.local` 或系统配置，不增加系统启动钩子，不处理其他插件目录。
  不重打 NVIDIA 驱动包，不修改或移除旧版发布附件。

## 验证

完整 PHP 套件与 63 项 Python 测试通过，包括固定未修改的原生 `rc.modules`、真实
`installpkg --root` 的隔离启动链，多 build 共存、运行中选择/下次启动切换构建、跨内核准备、
迁移和中断恢复、关闭恢复、原生证据不符、已加载模块、原 UUID 初始化、幂等和占用/失败。

真实本机 nginx/PHP-FPM 鉴权网关验证上传、取消、失败、删除及明确选包；浏览器回归覆盖
黑白主题、两档字号、窄屏、长内容、展开布局与字体隔离。模块元数据和 GPU 服务仍使用被动 fixture，
不是实机 GPU 验收。本轮没有连接、部署或操作 Unraid；由用户在 7.3.4 验收。

## 使用与边界

升级后核对缓存迁移和“Unraid 启动安装”标记，确认当前内核准备的是所需构建，再自行安排重启验收。
只改旧插件目录名不能替代这次本插件启动流程修复；其他插件遗留包仍需由用户自行移出原生扫描路径。

继续沿用已有插件加载时机，不通过系统钩子抢占顺序。若该时机 GPU 已被客户端占用，仍会明确报错，
不会停服务、强制接管、热卸载驱动或自动重启。保存的 UUID、PCI/profile 和既有配置保护保持不变。
