# Unraid vGPU Manager 2026.11.16.1 Alpha 12

第一阶段：将新增设备和只读详情彻底拆开，修正保存成功与失败的处理。

## 更新内容

- “添加设备”为固定独立面板，不再切换成编辑；“生成 UUID”不清空 GPU/profile。
- 列表“编辑”改为只读“详情”，分别呈现插件保存、系统定义和当前运行身份及差异。
  查看任意设备，包括系统设备，不改变新增草稿或自动接管设备。
- 新增保存使用独立 create-only 动作，UUID 已存在时明确拒绝，不覆盖旧配置；旧保存接口保持兼容。
- 确认保存成功后以 GET 刷新列表；失败、网络异常或结果未知保留输入，不自动重试、不重放 POST。
- 保留设备启停/移除门禁、双 CSRF、原生标签页按钮对齐及现有 profile 可用性判断。

保存配置不会立即启动设备；保存的设备仍参与之后启用的 vGPU 初始化，不是永久禁用草稿。
本版不包含重新配置、UUID 身份覆盖、驱动更新或启动入口迁移。

## 升级与验收

在 Unraid 插件页升级到 `2026.11.16.1`，重新打开 vGPU 管理页，无需为本次更新重启。
先在 7.3.4 核对详情不影响新增输入、重复原 UUID 被拒绝且原记录不变。
如测试真正的新配置，请确认是否需要让它参与下一次初始化；不要为界面测试随意保存占用显存的设备。

已通过硬件无关后端、PHP 页面及本地 HTTP 保存边界测试；浏览器测试覆盖详情独立性、
保存成功/失败/重复/异常和原生布局。测试未访问 NAS，也未执行 GPU 或服务操作。
实际 Unraid 浏览器交互与接管、系统升级仍需用户分别验收。
