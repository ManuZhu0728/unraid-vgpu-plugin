# Unraid vGPU Manager 2026.11.16.4 Alpha 15

修复 Alpha 14 中删除已下载驱动约 45 秒无响应、刷新后文件仍在的问题。

## 修复内容

- 删除、驱动下载和新增设备的纯文本异步表单改用普通 URL 编码，避免 multipart 在原生 nginx/PHP-FPM 鉴权子请求中阻塞，尚未进入业务后端就超时。
- 保留精确文件名、删除确认、双 CSRF、共享事务锁和所有缓存引用保护；不扩大可删除范围。
- 保留下载进度反馈、未保存草稿、明确失败提示和未知结果先 GET 核对、不自动重试的处理。
- 新增真实浏览器 → nginx 鉴权 → PHP-FPM → Application → 临时缓存文件的回归，覆盖实际 TXZ/MD5 删除、刷新后不再出现及旧 multipart 失败负对照。

## 7.3.4 升级与验收

1. 在 Unraid 插件页检查更新，升级插件到 `2026.11.16.4`，然后重新打开驱动管理页面。
2. 只选择不再需要、未被引用且按钮允许删除的旧包，确认删除后核对 TXZ 和同名 MD5；刷新后旧包不应再出现。
3. 当前选中、升级准备、安装及回退记录引用的构建仍应受保护；下载和新增设备沿用原有安全边界。

本次界面修复不要求主动重启服务器。未知结果仍应先重新打开页面核对，不能连续重试删除。
文件删除不可本地撤销，需要恢复时请从可信来源重新获取。

## 范围与已知限制

不改驱动安装、开机选包、服务、GPU 运行时或重新配置逻辑，不重新打 NVIDIA 驱动包；保留旧版发布附件。
本次发布不连接、部署或操作 Unraid，实际 7.3.4 验收由用户完成。

二进制分块上传仍使用 multipart，原生鉴权链兼容性尚需单独适配；本版没有把纯文本编码方案用于 File/Blob，也不宣称修复了上传链路。
