# v2026.11.17.2-alpha.19

系统升级联动改用 Unraid 原生 post-hook，保留 changes.txt 目标识别和定时检查兜底。

## 改动

- 在原生插件管理器已有 post-hooks 扩展目录中，仅新增本插件自己的可执行入口。
  成功安装或更新 Unraid 系统后，同步复用现有驱动准备 CLI；其他插件、检查、卸载和失败事件跳过。
- 保留 changes.txt 第一段版本的目标内核识别、私有 GitLab 凭据、驱动版本/build 策略与多构建缓存。
  手动检查、原生入口和原有定时兜底使用同一事务锁；并发准备有界等待并复用结果。
- 发布目标内核唯一启动包后，重新核对启动 TXZ、MD5、选择记录及精确构建。
  状态写入成功后才通知就绪；旧 ready 回执也必须重新核验启动副本。
- 开机恢复关闭时只提示“已缓存、未准备启动安装包”，不会隐式启用驱动或 vGPU。
  启动副本损坏或发布失败不报就绪，保留已校验的缓存用于恢复。

## 验证

开发机隔离回归覆盖原生 7.3.4/7.4.0 post-hook 调度函数、真实 Bash 调用与同步顺序、失败和缺失后端、
并发等待/超时、重复检查去重、多 build 与切换、启动 MD5 损坏、不安全目标、缓存-only 提示及打包白名单。
原生启动、真实本机 nginx/PHP-FPM 鉴权网关和浏览器回归沿用既有套件。
这些是本地测试，不是 Unraid/GPU 实机验收。

入口设计参考
[hellomrli 的原生 post-hook](https://github.com/hellomrli/my-unraid-vgpu-manager/blob/6e214c16b5114c9b5cac46cfcc67e62c61dbfa21/source/usr/local/emhttp/plugins/dynamix.plugin.manager/post-hooks/my-unraid-vgpu-manager)。
目标内核按本插件策略继续从 changes.txt 读取；下载器、启动包分离与核验继续使用本插件已有实现。

## 范围与验收

没有修改 Unraid 原有文件、公共 Update Helper 或驱动安装/启动分工。
没有部署到 Unraid、修改服务器配置、安装驱动、停止服务或执行重启。
公共助手的 `Everything done` 不包含本插件任务；不要把它当作 GPU 驱动准备成功的依据。

请在 7.3.4 更新插件后，检查系统更新日志中的本插件准备结果；确认目标内核、构建号、
“Unraid 启动安装”标记及“新内核驱动已准备”通知，再同时确认系统更新完成。
开机恢复关闭时应只看到缓存完成提示；失败应明确报错且不会把系统更新本身标记失败。
保留旧内核与旧构建缓存，不需要重新打包驱动。
